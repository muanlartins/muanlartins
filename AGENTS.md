# muanlartins

Luan Martins' personal site and the home of the muanlartins channel: improving at games with the scientific method, in Brazilian Portuguese. Rocket League in the afternoons, and Valorant, learned from Silver, on Monday and Wednesday nights.

## Ground rules

- `README.md` is Luan's GitHub profile README, not documentation for this repo. Don't edit it.
- Luan writes the copy: timeline entries, rank summaries. Scaffold structure and leave `TODO` text for him rather than writing his voice.
  Topic texts are the exception: each is a written summary of the topic's video, drafted from its transcript (YouTube's automatic captions, readable in his browser even for drafts) in his terms, not new material.
- `brand/` is the source of truth for the identity (see `brand/README.md`). Don't delete anything in it, explorations included.
- **Before writing any text or building any screen**, read `brand/voz.md` (voice, words, formats) and
  `brand/interface.md` (tokens, type, layout, components, states), and check the change against their last section.
  When Luan settles something new about copy or UI, it goes into them in the same commit.
- Small changes go straight to `main`; bigger features go through a branch and PR. A push to `main` is a release (below), so run `pnpm lint` first.
- Commit messages are imperative and short, with no names.
- **Every new feature goes on the roadmap page** (`/canal/roadmap`, `content/changelog.ts`), once: one entry per
  feature, never one per improvement. When Luan decides on a new feature that won't be released the same day, add it
  to `UPCOMING` right then, in its own commit if need be. When it's released, add its entry at the top of `SHIPPED`
  in the same commit, with the credit of whoever suggested it, and take it out of `UPCOMING`; when an existing
  feature gets better, update its entry instead (or leave it alone). This holds for features made in RLR, in OBS or
  in the scripts too, not only the site's. Before touching it, read "The roadmap and the changelog" below: not
  everything goes in.

## Routines (skills)

The stream's recurring work is written down as skills in `.claude/skills/` (Luan calls them as `/name`; read
the one that fits before starting): `antes-da-live` (what not to run while he's on air, OBS checks),
`depois-da-live` (filing the material, the live's page, the videos of its matches, YouTube, release), `faxina`
(cleaning the Videos folder), `estudio` (shorts and commented videos with RLR's studio), `agenda` (the lives' schedule on the site and Twitch), `obs` (OBS from WSL,
`scripts/obs.mjs`), `filtros` (a new agent's abilities on the camera filters: the game's effects and sounds,
the page, the dock, the headless test) and `voltaic` (publishing his aim training to Valorant's aim page). When a routine changes, change its skill in the same commit.

## One codebase, two sites

Each build bakes in one locale (`NEXT_PUBLIC_LOCALE`, see `lib/site.ts`):

| Locale | Domain | Dev | Sections, in the header's order |
|---|---|---|---|
| pt (default) | muanlartins.com.br | `pnpm dev` → :3000 | `/` (the channel; `/canal` is the same page), `/conteudo`, `/pessoal`, `/profissional` |
| en | muanlartins.com | `pnpm dev:en` → :3001 (`.next-en`) | `/` (Luan's life; `/personal` is the same page), `/professional`: nothing else, since his audience abroad is professional |

`./run.sh` runs both with hot reload. Which site has which section is `SECTIONS_OF` and its home `HOME` in `lib/site.ts`; the English build skips the channel, the games, the profile, Pix and the mural (the game routes build one unlinked placeholder, `/_/_`, since a static export can't build none), the header's language switch shows only where the other site has the page, and the footer drops Twitch and YouTube there. The header names each section with an icon, and the footer shows the profiles as brand icons (`components/site/brand-icons.tsx`) with the privacy policy on its own line. Copy is written as `{ pt, en }` (`L10n`) and picked with `localize`. Content that exists in one language only, like the roadmap, sets `language`, and the other site marks it with a badge and asks YouTube for captions.

Next.js 16, static export (`output: "export"`), Tailwind v4 with the brand tokens in `app/globals.css` (the zinc ramp is redefined as Klein tints, so "gray" is bluish on purpose).

- **Valorant's aim page** at `/conteudo/valorant/aim` (`components/site/aim/`, `lib/voltaic.ts`; the game's `aim` in `content/valorant-home.ts`, so `aim` is a reserved page id like `fundamentals` and `ranked`): Luan's aim training with Voltaic, the aim community: their Valorant routine in Aimlabs every day and their Season 3 benchmark every Sunday. `scripts/voltaic.py --apply` copies every play from Aimlabs' own SQLite on the stream PC into `content/voltaic/<date>.json` (task, score, accuracy, seconds, and the seconds paused when it was: a paused attempt doesn't count, as in Voltaic's; files only grow); `content/voltaic-s3.json` is the benchmark (each level's 18 scenario ids, subcategories and rank thresholds); `lib/voltaic.ts` finds the benchmarks (a day with 12+ of a level's scenarios, each at the day's best) and scores them with Voltaic's formula (energy per scenario, best per subcategory, harmonic mean of the nine, "Complete"). Below the scenarios, how the aim moves (`components/site/aim/flick-analysis.tsx`, `lib/mira.ts`): `scripts/mira.py --apply` reads Aimlabs' replays of the click scenarios themselves (`Replay/<play>.avro`, a format worked out on 2026-11-17 and checked play by play against each header's shots, targets and hits; only the last 50 plays have one) into `content/mira/<date>.json`: per play, the flicks that stop short and that go past the target, how far the first movement goes (and where it ends, binned), the corrections, clicking while moving and its hits, the shake before the click, why the misses missed, and the median flick as a curve; the page sums the latest 14 days. Beside it, **the training against the matches** (`ranked-comparison.tsx`, `summarizeRanked`; Luan, 2026-11-20: his aim training as a tool, "o treino está chegando no jogo?"): `scripts/mira_ranked.py` measures his Valorant matches the same way, from the game's own replays (`%LOCALAPPDATA%\VALORANT\Saved\Demos\<match>.vrf`, recorded on the server: every player's view and position 128 times a second, each gun's magazine, each hit with its bone), read by vrfkit (github.com/yakisoba0728/vrfkit, built outside the repo in `~/.local/share/vrfkit`; Riot scrambles each patch's replays, so a patch needs vrfkit's `git pull` and build before its matches read), with the same function as Aimlabs' (`mira.medir`, `resumo`): a fight's first shot is the flick, the target the head of the enemy nearest the crosshair as Luan saw it; plus the shots that hit, the head, the first shot walking and where the crosshair waited, into `content/mira-ranked/<date>.json`. Each match is checked first: his rebuilt view must pass, at the median, within a degree of where his own bullets landed. Nothing of the other players is kept. **It all follows by itself** (`scripts/mira_auto.py`, called every minute by `valorant.py`, never while live): the replays of the matches `valorant.py` queued are downloaded as the game's "Download" does (a signed link from Valorant's match history); once Aimlabs closes after new plays, `voltaic.py` and `mira.py` run; new replays are measured; and whatever changed in `content/voltaic`, `content/mira` and `content/mira-ranked` goes to main in one commit (`publicar.por_varios`), each script run over a copy of main's files, so the working copy is never touched.

## Fundamentals: "Como estou aprendendo"

From Valorant on, a game's fundamentals are written as how Luan is learning it, not as lessons: each topic is what
he learned about one concept, with the best sources he found credited under it (`sources` on a topic: title,
author, link; the page lists them as "Onde aprendi"). Only what the game doesn't say anywhere: no settings, no
menus, nothing the game's own screens explain. Topics come from Luan, a few at a time.

Every game's fundamentals are the same page (`roadmap-page.tsx`): the rail with its ranks, each rank's topics or "coming soon", the game's marker rolling down it (Rocket League's 3D ball, Valorant's ultimate orb, `ult-orb.tsx`) and its scene behind (the Octane, an agent).

A game can redo its fundamentals as a new **edition** (Rocket League's v2 will): a new roadmap file with a new `id`
(the saved progress is per roadmap, so the old one's stays), the same `game` and `edition: 2`, put first in the
game's `roadmaps`. The newest is at `/fundamentals`; each older one moves to `/fundamentals/v<n>` and links the
newest, and the newest links them. Every edition's topics keep living at `/conteudo/<game>/<topic>`, so published
links never break; that's why a topic id can't repeat across a game's editions (the build refuses it).

## The Rocket League roadmap

A usaco.guide-style path at `/conteudo/rocket-league/fundamentals`, inside Rocket League's home. `content/rocket-league.ts` holds ranks → pillars (Mecânica, Estratégia) → concepts → topics. Luan plans topics and tracks recording in an Obsidian note outside the repo (`- [ ] Rank · Topic`; `#gravando` = recorded, editing; `[x]` = published). The note is the source of truth for what exists; this file follows it.

How the page works:

- **Progress** lives in the visitor's browser (`localStorage` key `progress:<roadmap>`, statuses `practicing` / `done`), read with `useProgress`. Every change fires the `roadmap-progress` event with the progress before and after it, which is what celebrations listen to, so loading a page never triggers one.
- **Ranks progress independently** (`rankFills`), and nothing is locked. The visitor's rank is the lowest unfinished one (`currentRank`). Each rank's in-game emblem climbs its divisions I → III as its topics are done (`divisionOf`). Moving up a rank or a division shows a banner and confetti.
- **The rail** (`components/ui/timeline.tsx`) fills each rank's stretch with its own progress; the 3D ball (`rolling-ball.tsx`) rolls to the tip.
- **The scene follows scrolling, not progress.** The page glows in the colour of the rank being read, and the Octane behind it (`garage.tsx`, 20% opacity) air rolls as the page scrolls, both ways, and takes that rank's paint (`paint` on a rank overrides its colour: silver's legible text colour is too dark for chrome; unranked is matte primer). Topic pages have the ball large in the bottom-left corner (`ball-backdrop.tsx`), rolling with scroll.
- **Air roll physics** (`lib/air-roll.ts`) is RocketSim's spin model at 120 ticks/s, ported from Luan's Losfeld visualizer: air roll left with the stick turning clockwise. A replay records each tick so scrolling can scrub it either way.

## Release

A push to `main` releases both sites: CI lints, builds both locales and syncs them to S3 behind two CloudFront distributions, then clears their caches. A failing lint or build stops the release. Pull requests run the same build without publishing.

Hosting is Luan's personal AWS account (stack `muanlartins-site` from `infra/site.yml`, which he applies in the console). CI reaches it through GitHub OIDC with the repository variables `AWS_ROLE_ARN`, `SITE_BUCKET`, `DISTRIBUTION_PT` and `DISTRIBUTION_EN`, and `PERFIL_FUNCTION`, `SIGMA_FUNCTION` and `PIX_FUNCTION` (the stack's outputs `PerfilFunction`, `SigmaFunction` and `PixFunction`) to deploy the APIs' code (a function whose variable isn't set yet is skipped). AWS credentials on a local machine may belong to another account: never use them for this site.

Both distributions also send `/rlr/*` to RLR, the replay player, on GitHub Pages (`muanlartins/rlr`, released by its own pushes); `/rlr` redirects to `/rlr/`.

A release costs well under a cent. Every build changes every page (Next.js embeds a random build id), so syncing only changed files would save little.
